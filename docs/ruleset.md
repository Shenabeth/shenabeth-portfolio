# RULESET

## TypeScript

- [ ] All files use TypeScript (`.ts` or `.tsx`)
- [ ] Explicit type annotations on all functions, variables, and props
- [ ] No `any` types (justified comment if unavoidable)
- [ ] Component props defined as interfaces at top of file
- [ ] Return types explicitly declared on functions
- [ ] Use `string | null` instead of optional types unless necessary

## File Comments

- [ ] Every file starts with a comment block:
```typescript
/*
 * File: ComponentName.tsx
 * Purpose: [What this file does and why it exists]
 * Dependencies: [Major imports, if notable]
 */
```

## Function Documentation

- [ ] Every function has a JSDoc comment above it
- [ ] Format:
```typescript
/**
 * [Brief description of what the function does]
 * 
 * @param {type} paramName - [Description of this parameter]
 * @returns {type} [Description of what is returned]
 */
function nameOfFunction(paramName: type): returnType {
  // implementation
}
```

Example:
```typescript
/**
 * Fetches all projects from the API
 * 
 * @param {string} token - Cognito access token
 * @returns {Promise<Project[]>} Array of projects
 */
async function fetchProjects(token: string): Promise<Project[]> {
  // implementation
}
```

## Naming Conventions

- [ ] **Components:** PascalCase (e.g., `HeroSection.tsx`, `ProjectCard.tsx`)
- [ ] **Functions/utilities:** camelCase (e.g., `formatDate()`, `fetchProjects()`)
- [ ] **Constants:** UPPER_SNAKE_CASE (e.g., `API_BASE_URL`, `MAX_FILE_SIZE`)
- [ ] **Types/Interfaces:** PascalCase (e.g., `ProjectType`, `UserData`)
- [ ] **CSS classes:** Generated by Tailwind (don't write custom class names)
- [ ] **Files:** Match component/function name exactly (e.g., `HeroSection.tsx`, `utils.ts`)

## Styling with Tailwind

- [ ] Use Tailwind utility classes for all styling
- [ ] Dark mode by default (no light mode in Phase 1)
- [ ] No custom CSS files (except globals.css for resets)
- [ ] If styling appears in more than one component, extract to `tailwind.config.ts` as a reusable token
- [ ] Component-specific styling allowed ONLY if that component is used on a single page
- [ ] All color, spacing, typography changes go in `tailwind.config.ts` (global config)
- [ ] shadcn/ui components used for all UI elements (buttons, cards, forms, etc.)
- [ ] Do NOT override shadcn/ui default styling; extend it in Tailwind config

## Responsive Design

- [ ] All components work on mobile (320px), tablet (768px), laptop (1024px), desktop (1440px)
- [ ] Use Tailwind responsive prefixes: `sm:`, `md:`, `lg:`, `xl:`, `2xl:`
- [ ] Mobile-first approach: write mobile styles first, then add responsive prefixes for larger screens
- [ ] Test every component at: 375px (iPhone), 768px (tablet), 1024px (laptop), 1440px (desktop)
- [ ] Images use `max-w-full h-auto` to prevent overflow
- [ ] Horizontal scroll on featured projects (see HOME.md for specifics)

## Code Quality

- [ ] No dead code or unused imports
- [ ] No console.log() in production code (use proper logging if needed)
- [ ] Extract common logic into shared utilities or hooks
- [ ] Keep functions small and focused (single responsibility)
- [ ] No nested ternaries; use early returns or conditional rendering instead
- [ ] Keep component files under 300 lines; split if larger

## Git & Version Control

- [ ] Commit messages: descriptive and lowercase (e.g., "add hero section component")
- [ ] No committing secrets or API keys (use .env.local)
- [ ] .gitignore includes: node_modules/, .env.local, .env.production, .next/, dist/

## Modular Architecture

- [ ] Each component is independent and reusable
- [ ] Props clearly document what a component needs
- [ ] No hardcoded values in components (use props or config)
- [ ] API calls isolated in lib/api.ts or lib/queries.ts
- [ ] Auth logic isolated in lib/auth.ts
- [ ] Database logic isolated in lib/dynamodb.ts (if needed)
- [ ] Utility functions in lib/utils.ts

## TypeScript Types

- [ ] Centralize all types in `src/types/index.ts`
- [ ] Use `interface` for object shapes, `type` for unions or primitives
- [ ] Import types from `src/types/` in all files that need them
- [ ] Example:
```typescript
// src/types/index.ts
export interface Project {
  id: string;
  title: string;
  description: string;
  techStack: string[];
}

// src/components/ProjectCard.tsx
import { Project } from '@/types';
```

## Environment Variables

- [ ] Frontend vars: `NEXT_PUBLIC_*` prefix (visible to client)
- [ ] Backend/Lambda vars: no prefix (server-only)
- [ ] Never hardcode API URLs, database names, or API keys
- [ ] Use .env.local for local development (git-ignored)
- [ ] Use .env.production for production secrets (git-ignored, deployed separately)

## No Debate

These are not suggestions. Enforce them on every line of code.
